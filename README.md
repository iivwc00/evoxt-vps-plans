## 机房分三档：香港、大阪、东京差多少

Evoxt 把机房分三档，同一套餐在三档里价格相同，区别在月流量配额和线路。

**标准网络（Standard）**：美国、英国、加拿大、德国、波兰、荷兰阿姆斯特丹、日本东京、马来西亚、澳大利亚悉尼。**优质网络（Premium）**：香港、日本大阪。**Premium Plus**：马来西亚（高级），流量配额最少。

机房总数官网没给准确数字，第三方测评里有 16 个、17 个、15+ 三种说法，按十余个区域理解就行。

**香港**走三网 CN2 回程，电信、移动、联通回程都有 CN2 路由，到国内主要城市平均 30–50ms，晚高峰能跑视频和流媒体。测评只给了这个区间，没有分运营商的逐项数据，但这是 Evoxt 全系里国内访问最正常的一档。

**日本大阪**官网标注“优质网络”，第三方称其走软银线路，回程路由比东京顺。资料里没有大阪的具体延迟数字，判断依据只有线路类型和回程走向。

**日本东京**属于标准网络，走国际 PCCW（AS3491），不是 CN2，也没有 9929、4837 这类优化。159 个国内节点的实测结果：

| 运营商 | 平均延迟 | 情况 |
| --- | --- | --- |
| 中国移动 | 179ms | 三网中最好，部分节点 40–180ms |
| 中国电信 | 336ms | 去程绕美国 |
| 中国联通 | 372ms | 去程绕法兰克福 |

绕在哪：电信从 163 骨干出发，经美国节点转 PCCW 进东京；联通走 AS4837 到法兰克福再转东京；移动走 AS9808 经香港 CMI 接 PCCW，是三条里唯一相对顺的。回程三网都走 PCCW，移动落到 CMI，电信联通没有专门优化。

东京到境外倒是很干净：本地 2ms、到香港约 50ms、洛杉矶约 113ms、法兰克福约 237ms。

所以东京这台机器的定位很清楚。访客在日本、东南亚、欧美，或者你本人在海外，它完全够用，亚太 50–80ms、欧美 113–237ms 是正常水平。访客在国内且以电信联通为主，336ms 和 372ms 会直接拖垮打开速度，这种需求应该看香港或大阪。

## 性能实测：$2.99 那档跑出了什么分数

第三方对东京 VM-0.5（$2.99）的实测：Geekbench 5 单核 1751、多核 1903，SysBench 单线程 5996 分，内存读取 73172 MB/s、写入 42334 MB/s。磁盘 I/O 在多个节点普遍 1000 MB/s 以上，部分能到 2 GB/s。

同价位的老款 Intel Xeon 节点，Geekbench 5 单核通常在 800–1200 之间。差距来自硬件代际，Evoxt 用的是 EPYC Genoa。频率方面，东京节点实测主频 3.70 GHz，洛杉矶节点约 4.2 GHz，官方宣传的上限是 6.0 GHz；作为对照，AWS、Azure、Google Cloud、DigitalOcean 的标准实例普遍在 2.2–2.4 GHz。

高频对哪类任务有意义：PHP 建站、Node.js API、Python 脚本、Telegram/Discord Bot，这些吃的是单线程响应，核心多不一定快。多核跑分 1903 也说明它不是跑并行计算的机器，要编译、转码、跑数据库集群，得从 VM-8 往上选。

低价档没有被砍频率，这是 Evoxt 产品线上比较少见的一点。VM-0.5 和 VM-16 的单核频率上限一样，差别只在核数、内存、硬盘、流量。
